# Rotating secrets

Secrets live only in Render env groups (`hp-api-secrets`, per environment), Vercel project settings and GitHub Actions secrets. Never in git, tickets or chat. Generate with `openssl rand -base64 48` (hex keys: `openssl rand -hex 32`). Use different values in every environment.

**Schedule:** every 12 months, on staff departure with access, and **immediately** on suspected leak (then also review logs for use of the old value).

**General procedure:** generate new value → update the env group in Render (staging first, verify, then production) → redeploy/restart `hp-api` **and** `hp-worker` (they share the group) → verify → record in the change log (who, when, which secret — never the value) → revoke the old value at the provider.

| Secret                                                                          | Impact of rotating                                                                                                                                                                                         | Procedure notes                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_ACCESS_SECRET`                                                             | All access tokens become invalid at once. Clients refresh silently using their refresh token, so users mostly don't notice; in-flight requests may 401 once.                                               | Rotate any time; low risk.                                                                                                                                                                                                                                                                                                                              |
| `REFRESH_TOKEN_PEPPER`                                                          | All refresh tokens stop matching → **every customer and admin is logged out**. Until the backend switches order-lookup to `ORDER_LOOKUP_SECRET`, it also changes guest order lookup tokens (see next row). | Rotate off-peak; announce to admins (they must log in again with 2FA). On a leak, rotate immediately regardless.                                                                                                                                                                                                                                        |
| `ORDER_LOOKUP_SECRET`                                                           | Guest order lookup tokens are an HMAC of the order id under this secret. Rotating it **invalidates the order links in previously sent emails** (by design). Guests then need support or a resent link.     | Rotate only on leak or yearly. Tell support beforehand so they can resend lookup links on request. When the backend change lands, re-check this against `apps/api/src/modules/orders/lookup-token.ts`: as of 2026-10-11 the code stores a hash of the token, so old links would keep matching unless the backend re-derives the token when it verifies. |
| `TOTP_ENCRYPTION_KEY`                                                           | Encrypts admin 2FA seeds at rest. Replacing it **breaks every admin's 2FA** unless seeds are re-encrypted.                                                                                                 | Needs a backend re-encryption migration (decrypt with old, encrypt with new, both keys present for one deploy). Do not rotate by just swapping the value.                                                                                                                                                                                               |
| `COOKIE_SECRET`                                                                 | Signed cookies (guest cart id) become invalid → guest carts are lost.                                                                                                                                      | Off-peak.                                                                                                                                                                                                                                                                                                                                               |
| `STRIPE_SECRET_KEY`                                                             | Payments/refunds fail if wrong.                                                                                                                                                                            | Stripe → Developers → API keys → **Roll key** with an expiry (e.g. 12 h) so the old key keeps working during the deploy. Prefer a **restricted key** with only PaymentIntents, Refunds, Events read. Verify with a test-mode order on staging, then a live $1 order + refund after the production switch.                                               |
| `STRIPE_WEBHOOK_SECRET`                                                         | Signature checks fail → no orders marked PAID (SEV1).                                                                                                                                                      | Stripe → Webhooks → endpoint → **Roll secret** with an overlap expiry; update Render; redeploy; confirm deliveries return 2xx in the Stripe dashboard; see [stripe-webhooks.md](stripe-webhooks.md) for any failures during the window.                                                                                                                 |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`                                     | Admin image uploads (presigned URLs) and report exports fail.                                                                                                                                              | Cloudflare → R2 → Manage API tokens → create a new token scoped to the one bucket (Object Read & Write) → update Render → redeploy → test an image upload in admin → delete the old token.                                                                                                                                                              |
| `SMTP_URL` (Resend API key inside)                                              | Emails queue and retry (5 attempts, exponential), then fail.                                                                                                                                               | Resend → API keys → create (sending access, domain-scoped) → update `SMTP_URL` → restart worker → check a password-reset email arrives → revoke old key.                                                                                                                                                                                                |
| `SENTRY_DSN`                                                                    | Errors stop being reported if wrong.                                                                                                                                                                       | DSNs are not secret-critical; rotate only if abused (Sentry → Client Keys).                                                                                                                                                                                                                                                                             |
| Vercel/Render deploy hooks, `VERCEL_TOKEN`, `GITLEAKS_LICENSE` (GitHub secrets) | CI/CD deploys fail.                                                                                                                                                                                        | Regenerate at the provider, update GitHub → Settings → Secrets and variables → Actions.                                                                                                                                                                                                                                                                 |
| Database password                                                               | Render-managed; API/worker get it via `fromDatabase`.                                                                                                                                                      | Render support / recreate credentials; redeploy services.                                                                                                                                                                                                                                                                                               |

After any rotation of a leaked secret: search Better Stack Logs / Cloudflare events for activity using the old credential since the suspected leak time, and record findings in the incident doc.
